MedCare – Project Report

ABSTRACT

MedCare is a full-stack web-based Healthcare and Appointment Management System designed to digitize and streamline the interaction between patients, doctors, and healthcare administrators. The system addresses the inefficiencies of traditional paper-based appointment scheduling by providing a centralized, role-based digital platform accessible from any modern web browser.

The application supports three distinct user roles — Patient, Doctor, and Admin. Patients can register, search for doctors by specialization, book appointments, view prescriptions, and track appointment history. Doctors can manage their appointment queue, confirm or reject requests, write digital prescriptions, and view analytics. The system also features automated email notifications for appointment bookings and status changes.

The frontend is built using React 18 with TypeScript, styled with Tailwind CSS and Radix UI components. The backend is powered by Node.js with Express 5, using Passport.js for session-based authentication. Data is persisted in a PostgreSQL database managed through Drizzle ORM. Email notifications are delivered via Nodemailer with Gmail SMTP. The application is containerized using Docker and is deployable on platforms such as Render and Netlify.

The system demonstrates a modern, scalable architecture with clean separation of concerns, type-safe API contracts shared between frontend and backend, and a responsive user interface suitable for both desktop and mobile devices.

Keywords: Healthcare Management Appointment Booking React Node.js PostgreSQL Drizzle ORM TypeScript REST API Email Notifications

Chapter 1: Introduction

1.1 Background of the Project

The healthcare industry is one of the most critical sectors in any society, yet it continues to face significant operational challenges — particularly in the management of patient appointments, doctor availability, and medical records. In many hospitals and clinics, appointment scheduling is still handled manually through phone calls, physical registers, or fragmented software tools that do not communicate with each other.

With the rapid advancement of web technologies and the widespread adoption of the internet, there is a growing opportunity to digitize healthcare workflows. A web-based healthcare management system can eliminate redundant paperwork, reduce waiting times, improve communication between patients and doctors, and provide data-driven insights to healthcare providers.

MedCare was conceived as a response to these challenges — a modern, full-stack web application that brings patients, doctors, and administrators onto a single unified platform.

1.2 Purpose of the System

The primary purpose of MedCare is to provide a seamless digital experience for healthcare appointment management. The system serves three types of users:

  • Patients — can register, find doctors, book appointments, and view their prescriptions online.
  • Doctors — can manage their appointment schedule, confirm or reject requests, write digital prescriptions, and view analytics about their practice.
  • Administrators — have oversight of the system and can manage hospital and doctor data.

The system also automates email communication, sending notifications to both patients and doctors when appointments are booked or when their status changes.

1.3 Problem Statement

Traditional healthcare appointment systems suffer from several key problems:

  • Patients must physically visit or call a clinic to book an appointment, leading to long queues and wasted time.
  • There is no centralized record of a patient's appointment history or prescriptions.
  • Doctors have no digital tool to manage their schedule, confirm appointments, or issue prescriptions electronically.
  • Communication between patients and doctors is slow and unreliable, often relying on phone calls.
  • There is no analytics or reporting capability for doctors to understand their patient load and trends.

1.4 Objectives of the Project

  • To develop a role-based web application for patients, doctors, and administrators.
  • To enable patients to search for doctors by specialization and book appointments online.
  • To allow doctors to manage their appointment queue and issue digital prescriptions.
  • To implement automated email notifications for appointment events.
  • To provide an analytics dashboard for doctors to track appointment trends.
  • To ensure secure authentication using session-based login with password hashing.
  • To build a responsive, accessible UI that works on both desktop and mobile devices.
  • To design a normalized relational database schema using PostgreSQL.

1.5 Scope of the Project

The scope of MedCare covers the following functional areas:

  • User registration and login for patients and doctors with role-based access control.
  • Doctor discovery with search and filter by specialization.
  • Appointment booking, confirmation, rejection, completion, and cancellation workflows.
  • Digital prescription creation and viewing.
  • Email notification system for appointment lifecycle events.
  • Analytics dashboard with charts for appointment trends and status breakdown.
  • Profile management for both patients and doctors.
  • Hospital data management with associated doctor listings.

The system does not currently cover telemedicine (video consultations), payment processing, or integration with external Electronic Health Record (EHR) systems — these are identified as future enhancements.

Chapter 3: System Analysis

3.1 Existing System

In the conventional healthcare appointment system, patients must physically visit a hospital or clinic, or call the reception desk to schedule an appointment. The receptionist manually records the appointment in a register or a basic spreadsheet. Doctors are informed of their schedule through printed lists or verbal communication. Prescriptions are handwritten and given to the patient on paper.

Drawbacks of the Existing System:

  • Time-consuming and inconvenient for patients — requires physical presence or phone calls.
  • High risk of scheduling errors, double-bookings, and lost records.
  • No centralized patient history or prescription records.
  • No automated notifications — patients may forget appointments.
  • Doctors have no visibility into their upcoming schedule from outside the clinic.
  • No data analytics or reporting for hospital management.
  • Paper prescriptions can be lost, misread, or tampered with.

3.2 Proposed System

MedCare proposes a fully digital, web-based appointment management system that replaces manual processes with an automated, role-based platform. The system provides:

  • Online registration and login for patients and doctors.
  • A searchable doctor directory with specialization filters.
  • A complete appointment lifecycle: booking → confirmation/rejection → completion/cancellation.
  • Digital prescription creation and storage linked to appointments.
  • Automated email notifications at every stage of the appointment lifecycle.
  • An analytics dashboard with charts for appointment trends.
  • A responsive web interface accessible from any device.

Chapter 5: Modules Description

5.1 Authentication Module

The authentication module handles user registration, login, logout, and session management. It uses Passport.js with the LocalStrategy for username/password authentication. Passwords are hashed using Node.js's built-in crypto.scrypt function with a random salt, making them resistant to rainbow table attacks. Sessions are stored server-side using express-session with memorystore (development) or connect-pg-simple (production).

Key Features:

  • Secure password hashing with scrypt + random salt
  • Timing-safe password comparison to prevent timing attacks
  • Role-based registration: patients provide age/gender/contact; doctors provide specialization/experience/fee
  • Protected routes using req.isAuthenticated() middleware
  • Session persistence across page refreshes

5.2 Patient Module

The patient module provides all functionality available to registered patients. After login, patients are directed to their dashboard showing appointment statistics and upcoming visits.

Key Features:

  • Dashboard: Overview of total, pending, and confirmed appointments with quick action buttons.
  • Find Doctors: Browse all registered doctors with search by name and filter by specialization. Each doctor card shows their hospital, experience, and consultation fee.
  • Book Appointment: A dialog form allows patients to select a date, time, and reason for visit. Validation prevents past-date bookings.
  • Appointments: View upcoming (pending/confirmed) and historical (completed/cancelled/rejected) appointments in a tabbed interface. Patients can cancel pending or confirmed appointments.
  • Prescriptions: View all prescriptions issued by doctors, showing medicine names, dosages, frequencies, and instructions.
  • Profile: Update personal information including name, email, age, gender, contact, and medical history.

5.3 Doctor Module

The doctor module provides tools for healthcare professionals to manage their practice digitally.

Key Features:

  • Dashboard: Overview of appointment statistics with quick links to confirm requests, write prescriptions, and view analytics.
  • Appointments: View all incoming appointment requests. Doctors can confirm or reject pending appointments, and mark confirmed appointments as completed.
  • Prescriptions: Write digital prescriptions for confirmed/completed appointments. The prescription form allows adding multiple medicines with name, dosage, and frequency, plus additional instructions. Saving a prescription automatically marks the appointment as completed.
  • Analytics: Visual charts showing appointment trends over the last 7 days (bar chart), status breakdown (pie chart), and most active patients (horizontal bar chart).
  • Profile: Update specialization, experience, consultation fee, and availability schedule.

5.4 Appointment Booking Module

The appointment booking module manages the complete lifecycle of a medical appointment.

Appointment Status Flow:

pending  →  confirmed  →  completed

pending  →  rejected      pending / confirmed  →  cancelled
  • Patients create appointments with status pending.
  • Doctors can confirm or reject pending appointments.
  • Doctors can mark confirmed appointments as completed.
  • Patients can cancel pending or confirmed appointments.
  • Each status change triggers an automated email notification.

5.5 Prescription Module

Doctors can create digital prescriptions linked to specific appointments. Each prescription stores:

  • A list of medicines with name, dosage (e.g., "500mg"), and frequency (e.g., "2x daily").
  • Additional instructions (e.g., "Take after meals, avoid alcohol").
  • The date of prescription creation.
  • A foreign key link to the appointment, enabling patient history tracking.

Patients can view all their prescriptions from the Prescriptions page, enriched with doctor and appointment details.

5.6 Notification / Email Module

The email module uses Nodemailer with Gmail SMTP to send HTML-formatted emails. Emails are sent asynchronously using setImmediate to avoid blocking API responses.

Email Triggers:

  • Appointment Booked: Two emails sent — one to the patient (booking confirmation) and one to the doctor (new request notification).
  • Status Changed: One email sent to the patient when their appointment is confirmed, rejected, completed, or cancelled.

All emails use a branded HTML template with the MedCare logo, appointment details, and status badges.

5.7 Analytics Module

The analytics module provides visual insights into appointment data using Recharts. It is accessible to doctors and administrators.

  • Summary Cards: Total appointments, completed, pending, and cancelled/rejected counts.
  • 7-Day Trend Bar Chart: Daily appointment count for the past week.
  • Status Breakdown Pie Chart: Distribution of appointment statuses (confirmed, completed, pending, rejected, cancelled).
  • Top Patients Bar Chart: Horizontal bar chart showing the most active patients by appointment count.

7.1.1 Database Schema Definition (shared/schema.ts)

The database schema is defined using Drizzle ORM's table builder. This TypeScript file is shared between the frontend and backend, ensuring type safety across the entire stack. Below is the appointments table definition: 

export const appointments = pgTable("appointments", {

  patientId: integer("patient_id").notNull()

7.1.2 Authentication (server/auth.ts)

Passwords are hashed using Node.js's crypto.scrypt with a 16-byte random salt. The hash and salt are stored together as hash.salt. Comparison uses timingSafeEqual to prevent timing attacks. 

export async function hashPassword(password: string) {
  const salt = randomBytes(16).toString("hex");
  const buf = (await scryptAsync(password, salt, 64)) as Buffer;
  return `${buf.toString("hex")}.${salt}`;
}

async function comparePasswords(supplied: string, stored: string) {
  const [hashed, salt] = stored.split(".");
  const hashedBuf = Buffer.from(hashed, "hex");
  const suppliedBuf = (await scryptAsync(supplied, salt, 64)) as Buffer;
  return timingSafeEqual(hashedBuf, suppliedBuf);
}

7.1.3 Appointment Booking API (server/routes.ts)

When a patient books an appointment, the server validates the input using Zod, creates the record, and sends email notifications asynchronously: 

app.post(api.appointments.create.path, async (req, res) => {
  if (!req.isAuthenticated() || req.user!.role !== "patient")
    return res.sendStatus(401);

  const patient = await storage.getPatientByUserId(req.user!.id);
  const input = insertAppointmentSchema.parse({
    ...req.body, patientId: patient.id
  });
  const appointment = await storage.createAppointment(input);

  // Send emails in background (non-blocking)
  setImmediate(async () => {
    await sendAppointmentBookedEmails({ ... });
  });

  res.status(201).json(appointment);
});

7.1.4 React Query Hook for Appointments (client/src/hooks/use-appointments.ts)

The frontend uses TanStack Query for server state management. The hook fetches appointments and provides a mutation for creating new ones: 

export function useAppointments() {

export function useCreateAppointment() {
  const queryClient = useQueryClient();
  return useMutation({
    mutationFn: (data) =>
      fetch("/api/appointments", {
        method: "POST",
        body: JSON.stringify(data),
      }).then(r => r.json()),
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ["/api/appointments"] });
    },
  });
}

7.1.5 Email Notification (server/email.ts)

Nodemailer is configured with Gmail SMTP. HTML emails are generated using template functions that produce branded, responsive email layouts: 

export async function sendAppointmentBookedEmails(data) {
  if (!process.env.EMAIL_USER || !process.env.EMAIL_PASS) return;

  const transporter = nodemailer.createTransport({
    service: "gmail",
    auth: { user: process.env.EMAIL_USER,
            pass: process.env.EMAIL_PASS }
  });

  // Send to patient and doctor in parallel
  await Promise.all([
    transporter.sendMail({
      to: data.patientEmail,
      subject: `Appointment Booked with Dr. ${data.doctorName}`,
      html: appointmentBookedPatientHtml(data),
    }),
    transporter.sendMail({
      to: data.doctorEmail,
      subject: `New Appointment Request from ${data.patientName}`,
      html: appointmentBookedDoctorHtml(data),
    }),
  ]);
}

7.1.6 Protected Route Component (client/src/components/ProtectedRoute.tsx)

The ProtectedRoute component wraps pages that require authentication. It checks the current user's role and redirects unauthorized users: 

export function ProtectedRoute({ component: Component, allowedRoles }) {
  const { user, isLoading } = useAuth();

  if (isLoading) return <LoadingSpinner />;
  if (!user) return <Redirect to="/login" />;
  if (allowedRoles && !allowedRoles.includes(user.role))
    return <Redirect to="/dashboard" />;

  return <Component />;
}

Chapter 9: Advantages of the System

  • 24/7 Accessibility: Patients can book appointments at any time from any device with internet access, eliminating the need for phone calls or physical visits.
  • Role-Based Access Control: Each user type (patient, doctor, admin) sees only the features relevant to their role, improving usability and security.
  • Automated Email Notifications: Both patients and doctors receive timely email updates at every stage of the appointment lifecycle, reducing missed appointments.
  • Digital Prescription Management: Prescriptions are stored digitally, eliminating the risk of lost or illegible handwritten prescriptions. Patients can access them anytime.
  • Data-Driven Analytics: Doctors can view appointment trends, status breakdowns, and patient activity through interactive charts, enabling better practice management.
  • Type-Safe Full Stack: Shared TypeScript schemas between frontend and backend prevent data contract mismatches and reduce runtime errors.
  • Secure Authentication: Passwords are hashed with scrypt + salt. Timing-safe comparison prevents timing attacks. Session-based auth prevents token theft.
  • Responsive Design: The Tailwind CSS-based UI adapts to all screen sizes, making the system usable on mobile phones, tablets, and desktops.
  • Containerized Deployment: Docker support enables consistent deployment across development, staging, and production environments.
  • Scalable Architecture: The separation of frontend, backend, and database into distinct layers allows each to be scaled independently.

Chapter 10: Limitations of the System

  • No Payment Integration: The system does not currently support online payment for consultation fees. Patients must pay in person.
  • No Telemedicine: Video or audio consultations are not supported. All appointments are assumed to be in-person.
  • No Real-Time Notifications: In-app notifications are not real-time (no WebSocket push). Users must refresh to see updates.
  • No Admin Dashboard: While an admin role exists, a dedicated admin panel for managing users, hospitals, and system data is not fully implemented.
  • No Doctor Availability Enforcement: The system stores availability slots but does not enforce them during booking — patients can book any date/time.
  • No File Uploads: Patients cannot upload medical documents or reports. Doctors cannot attach files to prescriptions.
  • Email Dependency: The notification system requires valid Gmail SMTP credentials. If not configured, email notifications are silently skipped.
  • Single Hospital per Doctor: Each doctor can only be associated with one hospital. Independent or multi-location practitioners are not fully supported.
  • No Appointment Reminders: The system does not send reminder emails before scheduled appointments.

Chapter 11: Future Enhancements

The following enhancements are planned for future versions of MedCare:

  • Telemedicine / Video Consultations: Integrate WebRTC or a third-party service (e.g., Twilio, Daily.co) to enable video consultations directly within the platform.
  • Online Payment Gateway: Integrate Razorpay, Stripe, or PayPal to allow patients to pay consultation fees online at the time of booking.
  • Real-Time Notifications: Implement WebSocket-based push notifications so users receive instant in-app alerts without refreshing.
  • Admin Dashboard: Build a comprehensive admin panel for managing users, hospitals, doctors, and viewing system-wide analytics.
  • Appointment Reminders: Send automated reminder emails 24 hours and 1 hour before scheduled appointments using a job scheduler (e.g., node-cron).
  • Doctor Availability Enforcement: Validate appointment bookings against the doctor's defined availability slots and prevent double-bookings.
  • Medical Document Upload: Allow patients to upload lab reports, X-rays, and other documents that doctors can view before the appointment.
  • Mobile Application: Develop a React Native mobile app for iOS and Android, sharing the same backend API.
  • EHR Integration: Integrate with standard Electronic Health Record (EHR) systems using HL7 FHIR APIs for interoperability with existing hospital systems.
  • Multi-Language Support: Add internationalization (i18n) support to make the platform accessible in multiple languages.
  • AI-Powered Doctor Recommendation: Implement a recommendation engine that suggests doctors based on the patient's symptoms, location, and past appointment history.

Chapter 12: Conclusion

MedCare successfully demonstrates the development of a modern, full-stack healthcare appointment management system using contemporary web technologies. The project addresses real-world problems in healthcare administration by providing a digital platform that streamlines appointment booking, doctor-patient communication, prescription management, and analytics.

The system was built with a strong emphasis on type safety, security, and user experience. The use of TypeScript across the entire stack, shared schema definitions, and Zod validation ensures data integrity from the database to the user interface. The role-based access control system ensures that each user type interacts only with the features relevant to their role.

The project demonstrates proficiency in modern web development practices including: React component architecture, RESTful API design, relational database modeling, session-based authentication, asynchronous email delivery, and containerized deployment.

While the current version has certain limitations — such as the absence of payment processing and telemedicine features — the architecture is designed to be extensible, and a clear roadmap for future enhancements has been identified. MedCare serves as a solid foundation for a production-grade healthcare management platform.
