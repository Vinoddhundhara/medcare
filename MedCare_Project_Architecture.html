📌 1. Project Overview
What is MedCare and why was it built?

Problem Statement

In traditional healthcare, booking a doctor appointment requires phone calls, long waiting times, and manual paperwork. Patients have no visibility into doctor availability, and doctors struggle to manage their schedules efficiently. There is no centralized system for prescriptions, notifications, or video consultations.

Our Solution

MedCare is a full-stack web application that digitizes the entire doctor appointment lifecycle — from booking to prescription — with real-time email notifications, video consultation links, analytics, and role-based access for patients, doctors, and admins.

🎯 Purpose

Simplify healthcare access by providing a digital platform for appointment booking, management, and communication between patients and doctors.

👥 Target Users

Patients seeking medical care, doctors managing their practice, and hospital administrators overseeing operations.

🌍 Real-World Use

Can be deployed for clinics, hospitals, or independent doctors. Scalable to handle thousands of appointments.

📧 8. Email Notification System
Automated HTML emails sent at every key appointment event

📬 When Appointment is Booked

Patient receives: Appointment confirmation with doctor name, date, time, hospital, reason, and status badge.

Doctor receives: New request alert with patient name, age, gender, date, and action prompt to log in.

🔄 When Status Changes

Confirmed: Patient gets green confirmation email with arrival tips.

Rejected: Patient gets red email suggesting to rebook.

Completed: Patient gets blue email with prescription reminder.

Cancelled: Patient gets grey email with rebooking suggestion.

🎥 When Video Link is Added

Patient receives a professional email with a large "Join Video Call" button, the meeting link, appointment details, and tips for a smooth video consultation.

⚙️ Technical Implementation

Library: Nodemailer v6
Provider: Gmail (App Password)
Method: setImmediate() — emails sent in background, never blocking API response
Templates: Pure HTML/CSS inline styles for email client compatibility

How users are authenticated and data is protected

Security Measures

  • Passwords hashed with Scrypt + random salt (never stored plain)
  • Sessions stored in PostgreSQL (not memory)
  • All sensitive routes check req.isAuthenticated()
  • Role-based access: patients can't access doctor routes
  • Ownership checks: doctors can only modify their own appointments
  • All fetch calls use credentials: "include" for cookie auth
  • Zod validates all incoming request bodies
  • URL encoding for special characters in DB connection string
⭐ 10. Key Features Deep Dive
The most important features and how they work technically

🔔 Smart Notification System

Notifications are computed client-side from appointment data — no separate DB table needed. Each notification has a unique ID. Seen IDs are stored in localStorage per user. The sidebar Bell icon shows a red dot badge with count of unseen notifications. Clicking a notification marks it as seen and removes the alert instantly.

🎥 Video Call Integration

Works with any video platform (Google Meet, Zoom, Teams). Doctor pastes a link on confirmed appointments. Link is saved to the appointments table. Patient sees a "Join Call" button. An email with the link is sent automatically. URL validation ensures only valid links are accepted.

📊 Real-time Data Updates

TanStack Query with staleTime: 0 ensures data is always fresh. After any mutation (confirm, cancel, prescribe), invalidateQueries with refetchType: "all" forces all pages (Dashboard, Analytics, Appointments) to refetch simultaneously, even if they are not currently visible.

💊 Prescription System

Doctors write prescriptions linked to specific appointments. Each prescription stores medicines as a JSON array with name, dosage, and frequency. Writing a prescription automatically marks the appointment as "completed". Patients can view all their prescriptions in one place.

🛡️ Role-Based Access Control

Three roles: patient, doctor, admin. Each role sees different sidebar links. ProtectedRoute component blocks unauthorized access at the frontend. Every API endpoint independently verifies the user's role and ownership. Double security: both client and server enforce access rules.

📈 Analytics Dashboard

Available to doctors and admins only. Shows appointment trends over the last 7 days as a bar chart, status breakdown as a pie chart, and most active patients as a horizontal bar chart. All computed from live appointment data using Recharts.

💡 12. Why I Built This Project
Motivation, learning outcomes, and real-world impact

🎓 Learning Goals

To build a complete full-stack application from scratch using modern technologies. Learn how to design a relational database, build a REST API, implement authentication, and create a responsive React frontend — all connected together.

🌍 Real-World Problem

Healthcare appointment management is still largely manual in many places. Long phone queues, missed appointments, and no digital records are common problems. MedCare solves this with a digital-first approach accessible from any browser.

🚀 Industry Relevance

Uses the same tech stack as modern startups: React, Node.js, PostgreSQL, TypeScript. Implements real features like email notifications, video calls, and analytics that are found in production healthcare systems like Practo and Zocdoc.
